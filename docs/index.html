Gradient Boosted Trees from Scratch: AdaBoost, LogitBoost and XGBoost

How it was built

Part 1: A Tree That Reads Gradients

Every boosting method in chapter 18 of Murphy's book needs the same weak learner, so build one tree that serves them all. It sees only per-example gradients and Hessians (PML 18.5.5.2), works on binned features, and turns out to be exactly CART when you hand it the right statistics.

Part 2: Least-Squares Boosting

The simplest boosting there is (PML 18.5.1-18.5.2): each new tree fits what the current model still gets wrong. Reproduce the three rounds of Figure 18.6 on the book's own data, then measure what the learning rate really buys.

Part 3: AdaBoost from Exponential Loss

Derive AdaBoost.M1 the way PML 18.5.3 does, as forward stagewise fitting of the exponential loss, and check every line of the derivation on data: the weak learner, the step size, the weight update and the training bound. Then test the book's claim that the resulting scores are not probabilities.

Part 4: LogitBoost and Label Noise

Replace the exponential loss with log loss and a Newton step (PML 18.5.4, Algorithm 18.2). The same stumps with real-valued leaves do far better on some data, and that is not the reason the book gives. Then put the outlier claim to the test by flipping training labels.

Part 5: Gradient Boosting with Any Loss

Stop deriving a new algorithm per loss (PML 18.5.5). Fit each tree to the negative gradient, then re-solve its leaves for the loss you care about. Check Table 18.1 with finite differences, find out when the re-solve matters, test robust losses against outliers, and extend it all to many classes.

Part 6: XGBoost's Second-Order Boosting

Write the regularized second-order objective of PML 18.5.5.2 and check it against the real xgboost library, tree for tree. Add early stopping and feature sampling. Then ask what second-order information is really worth, and whether subsampling generalizes better, as the book says it can.

Part 7: Forests Against Boosting

With the tree you already have, bagging and random forests take about ten lines (PML 18.3-18.4). Reproduce the comparison of Figure 18.5 on the real spam split, then test why it comes out that way: boosting attacks bias, averaging attacks variance.

Part 8: Reading the Ensemble

Hundreds of trees are not readable, but two simple summaries are (PML 18.6): which features earned the gain, and how the prediction moves with each one. Run them on the boosted spam filter and compare what you find with Figures 18.9 and 18.10.
